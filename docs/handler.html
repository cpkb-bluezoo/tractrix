XmlHandler contract

The event vocabulary, ordering rules, streaming chunks, and buffer lifetimes you must honour.

XmlHandler is the sole consumer API for parse results. It mirrors Gonzalez XMLHandler: raw qNames, streamed content with an explicit end flag, and optional namespace events from NamespaceFilter. Every method has a default no-op except fatal_error.

Document-level order

  1. set_locator — may fire early; locator stays valid for the parse
  2. set_xml11 — after the XML declaration (or default 1.0)
  3. start_document
  4. Optional prolog: PIs, comments, then DTD (start_dtd … decls … end_dtd)
  5. Document element (see element order)
  6. Optional epilog: comments / PIs
  7. end_document

Element order

For <item id="42">text</item> the handler sees:

  1. start_element("item") — raw qName only
  2. Zero or more of:
    • namespace(prefix, uri) — only with NamespaceFilter; empty prefix = default NS
    • start_attribute(name, ty, declared, specified) then one or more attribute_value_content(value, end) (last chunk has end = true)
  3. end_attributes() — always once per element, even with zero attributes
  4. Content: characters, nested elements, comments, PIs, CDATA brackets, entity markers, …
  5. end_element() — no name; keep your own stack from start_element

Empty elements

<br/> still produces start_element → end_attributes → end_element with no character content in between.

Streaming chunks and end

Attribute values, character data, comment bodies, and PI data are streamed. One logical run may be one call or many. The end flag is true on the chunk that completes the run.

APINotes
attribute_value_content(value, end) Follows start_attribute; may be empty with end = true at a buffer boundary
characters(text, ignorable, end) Entities already expanded; ignorable is whitespace in element content when validation knows that
comment_data(text, end) After start_comment
pi_data(data, end) After pi_target

If the first call already has end = true, you may use the slice immediately with no buffering.

Buffer lifetimes and save_buffers

&str arguments are borrowed from the scanner’s working storage. They are valid only for the duration of the callback. Before the scanner reuses that storage (for example after a character reference, or at the end of a receive chunk), it calls save_buffers().

  • If you retain text across calls, copy it into owned storage.
  • If you were holding borrowed slices, copy them in save_buffers (or earlier).
  • Ignoring save_buffers while keeping borrows is undefined behaviour from the application’s point of view (dangling views into reused buffers).

Errors

MethodContract
fatal_error(message) Well-formedness (or similar) failure. Returning Err aborts the parse. The default implementation returns Err(ParseError::new(message)).
error(message) Recoverable — typically a validity constraint when validation is on. Parsing continues unless you return Err. Default is Ok(()).

Application code may also return Err from any other handler method to abort early.

Compared with SAX

There is no split into ContentHandler, LexicalHandler, and DeclHandler — one trait covers all. There is no Attributes object: attributes are streamed. end_element carries no name. Namespace events are optional and come from a filter stage, not from the scanner itself.
